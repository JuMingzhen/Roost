# 0004：便携 zip 发布，开机自启写当前用户的 Run 键

- 状态：提议
- 日期：2026-10-19
- 提出方：Claude Code
- 确认人：

## 背景

PRD 第 4 节：开机自启 v1 提供、默认关闭，首次启动时询问一次，之后可在设置页修改；通过 GitHub Release 分发，不做代码签名和自动更新。

用户 2026-10-19 决定发布包用**便携 zip**，解压即用，不做安装程序（PRD 第 4 节已按批准注明）。随之要定三件事：

- 自启用什么机制；
- 解压后的文件夹被挪动或删除时怎么办；
- 怎么卸载。

## 候选方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A（建议） | 在当前用户注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下写一项 `Roost`，值为带引号的 `Roost.exe` 完整路径 | 不需要管理员权限；只用 .NET 自带的 `Microsoft.Win32.Registry`，不增加依赖；任务管理器「启动应用」里能看到；测试可以换成单独的注册表键，不碰真实自启项 | 登记的是绝对路径，便携文件夹被挪走后会失效，需要程序自己修正 |
| B | 在「启动」文件夹（`shell:startup`）放一个快捷方式 | 用户在资源管理器里看得见 | 创建 `.lnk` 要用 COM（`WScript.Shell` 或 `IShellLink`），代码更多；同样有路径失效的问题；测试要动真实的「启动」文件夹或另做隔离 |
| C | 计划任务（登录时触发） | 可以设置延迟启动 | 要调用 `schtasks` 或任务计划 COM 接口，复杂度最高；对一个常驻小工具来说没有必要 |

## 实测数据

- 环境：用户的开发机，Windows 11 25H2（build 26200.9457，家庭中文版），单显示器，真实 200% 缩放。测试进程是**普通权限**（Medium Mandatory Level，未提权）。
- 方法：
  - `test.ps1` 的「开机自启」测试在临时键 `HKCU\Software\Roost.Tests.<随机>\Run` 下验证以下几点，结束时删除临时键，并核对真实 Run 键里的 `Roost` 项前后一致：
    - 开启、关闭、重复关闭；
    - 没开自启时 `Repair` 不会自己打开；
    - 登记的路径已不存在时改成当前位置；
    - 登记的是另一份还存在的 Roost 时不动。
  - `verify-system.ps1` 在设置窗口里打开开关并保存，确认注册表出现指向当前程序的自启项；重新打开设置，开关显示为开；关掉并保存后自启项消失。同样用临时键，并核对真实自启项未变。
  - 用当前构建产物（`Roost.exe`、`Roost.Core.dll`、`assets`）试打一个 zip，记录大小。
- 结果：
  - `test.ps1` 34/34；`verify-system.ps1` 通过（`autoStartToggleWritesRegistry: true`、`realAutoStartUntouched: true`，点击穿透 12/12）。普通权限下写入、删除都成功。
  - 运行前后 `HKCU\Software` 下没有残留的 `Roost*` 测试键；真实 Run 键里没有 `Roost` 项，测试前后一致。
  - 试打的 zip：解压后 414,534 字节，zip 298,521 字节（约 0.3 MB）。PRD 第 13 节的预期是约 8–15 MB，实际远小于预期，原因是 .NET Framework 4.8 是 Windows 自带的，不用打包运行时。
  - 注销或重启后是否真的自动启动，要用户在 M4 门禁里实测（「下一步」第 11 步）。

## 结论

采用方案 A。

## 影响

- 程序与数据分开：
  - 程序在用户解压的文件夹里，`Roost.exe`、`Roost.Core.dll`、`assets` 必须放在一起。
  - 数据在 `%LOCALAPPDATA%\Roost`。
  - 换个位置重新解压不影响数据。
- 文件夹被挪动：每次正常启动时，如果自启项指向的 `Roost.exe` 已经不存在，就改成当前位置（`AutoStart.Repair`）。
  - 指向的文件还在（例如另一份 Roost）时不动，以免开发时运行的构建抢走自启项。
  - 指定了 `ROOST_DATA_DIR` 的测试运行不做修正。
- 卸载（写进 README）：
  1. 在设置里关掉开机自启；
  2. 退出 Roost；
  3. 删除程序文件夹；
  4. 如需清除数据，再删除 `%LOCALAPPDATA%\Roost`，以及 Windows 凭据管理器里 Roost 的 API Key。
  - 如果先删了文件夹而没关自启，Run 键里会留下一项指向不存在的文件，登录时找不到程序，不会启动 Roost；这一项在任务管理器的「启动应用」里看得到。
- 已知限制：用户在任务管理器的「启动应用」里把 Roost 设为「已禁用」，Windows 把这个状态记在另一个注册表位置（`StartupApproved`）。这个格式没有官方文档，也没有在本机实测，所以 Roost 不读写它。这种情况下设置里的开关仍会显示为开，要恢复得回任务管理器里启用。
- 对 PRD 指标：没有新增依赖；包体积见上面的实测数据。
- PRD：不需要再修改（第 4 节的「便携 zip」已按用户批准写入）。
