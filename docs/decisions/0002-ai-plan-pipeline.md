# 0002：AI 改计划的调用与校验方式

- 状态：提议
- 日期：2026-09-23
- 提出方：Claude Code
- 确认人：

## 背景

PRD 第 8、9 节要求：用户自带 OpenAI 兼容模型；一句话转成对待办的操作；「今天 / 明天」按一天起点理解；任何改动先预览、确认后才生效；模型出错不能影响本地待办；单次调用成本不随使用时长增长。第 8.6 节还要求预设模型通过评测集，三类致命错误为 0。

需要决定：怎么调用模型、让模型输出什么、哪些判断交给模型、哪些在本地做。

## 候选方案

### 输出结构

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A（采用） | 提示词要求只输出一个 JSON 对象；客户端取第一个 `{` 到最后一个 `}` 解析 | 五家厂商都支持普通对话接口；能容忍模型包一层 ```json 代码块 | 依赖模型遵守格式；不遵守时按「没听懂」处理并原样展示回复 |
| B | 加 `response_format: {"type":"json_object"}` | 格式更稳 | 各家支持程度和参数细节不一，未实测前可能让某家直接 400 |
| C | function calling / tools | 结构最严格 | 各家兼容度差异更大；小模型工具调用质量参差 |

先用 A，拿到各家评测数据后再判断是否值得对个别预设加 B。

### 时间换算

| 方案 | 做法 | 结论 |
|---|---|---|
| 本地解析中文相对时间 | 模型只抽取「下周三下午」这类原文，本地换算 | 中文时间表达太多，本地规则难以覆盖，放弃 |
| 模型输出绝对日期（采用） | 提示词给出按一天起点计算的「今天 / 明天」和 14 天日期对照表（含本周 / 下周标注），模型直接输出 `YYYY-MM-DD` 与 `HH:mm` | 换算基准由本地代码统一给出，和清单筛选、过期判断用同一个 `TodoRules.LogicalDate`；本地只做格式校验和「早于现在」警示 |

### 待办引用

发送给模型的待办用短别名 `t1`、`t2`…，本地再映射回真实 id：比 32 位 GUID 省 token，也降低模型抄错 id 的概率。别名不在本次发送范围内的操作一律判无效。

## 实测数据

### 环境

- Windows build 26200，单显示器 200% 缩放，16 逻辑处理器；系统 .NET Framework 4.8 `csc.exe` 编译。
- 代码在 WSL 仓库中编辑，桌面验证在 Windows 本地目录镜像中运行。

### TLS 与连通性（2026-09-23）

不带 key 请求各预设的 `GET {base}/models`，看 HTTPS 能否建立并得到 401：

| 厂商 | 默认协议（`Ssl3, Tls`） | 显式开启 TLS 1.2 / 1.3 后 |
|---|---|---|
| DeepSeek | 401，580 ms | 401，198 ms |
| 通义千问 | 401，269 ms | 401，158 ms |
| Kimi | 401，263 ms | 401，198 ms |
| 智谱 | **握手失败**（HttpRequestException） | 401，97 ms |
| 豆包 | **握手失败**（HttpRequestException） | 401，171 ms |

原因：`csc` 直接编译的程序没有目标框架标记，.NET 4.8 按旧兼容模式只启用 SSL3 / TLS 1.0。因此 `AiClient` 静态构造时显式开启 TLS 1.2 / 1.3。

### 请求规模

11 条待办时系统提示词 2,178 字符（UTF-8 4,146 字节）。每次请求 = 提示词 + 一句话输入，输出上限 2,048 token。发送范围固定为「未完成 + 7 天内完成」（PRD 8.7），不随使用时长增长。

### 自动化验证

| 检查 | 命令 | 结果 |
|---|---|---|
| 解析、校验、发送范围、日期边界、整批应用与撤销、HTTP 失败分类、凭据存储 | `.\test.ps1` | 19/19 通过 |
| 评测集评分器自检（完美模型 / 故意犯错模型） | `.\test.ps1` 中的 `Roost.Eval.exe --self-test` | 70/70 通过、0 致命；故意犯错时查出 15 个致命错误并判为不达标 |
| 真实宠物窗口 + 本地假模型：思考动画、预览期间与取消后数据不变、确认整批生效、整批撤销、key 无效 / 没听懂 / 歧义 / 服务错误 / 用户取消 / 未配置 | `.\verify-ai.ps1` | 13/13 项通过 |
| 假 key 请求真实 DeepSeek 接口 | `Roost.Eval.exe run … deepseek` | 识别为 key 无效并中止，未继续计费 |

### 尚未实测

- **各预设推荐模型的评测集结果与延迟**：需要用户提供 key，见 `docs/PROGRESS.md`「待用户确认」。
- 方案 B（`response_format`）对格式稳定性的影响。

## 结论

采用：OpenAI 兼容 `chat/completions` 非流式请求，`temperature` 0；模型输出 JSON（方案 A）并直接给出绝对日期；本地负责全部校验、人话摘要、过去时间警示和确认后整批写入。

## 影响

- 新增对框架自带 `System.Net.Http.dll` 的引用，不引入第三方依赖，不影响安装包体积。
- 超时暂定 30 秒（PRD 8.8 交由设计确定），等评测集的真实延迟数据再定。
- 模型只「提议」操作；确认前不写入任何文件（`verify-ai.ps1` 直接比对数据文件字节）。
- 撤销 AI 新增的待办时直接移除该条，而不是软删除，因为它在用户点确认前并不存在。
- 预设推荐模型必须以评测报告为准；评测不过的模型不能放进预设。
