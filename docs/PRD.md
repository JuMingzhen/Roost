# Roost 产品需求文档（v1）

> 本文只描述需求和预期效果，不涉及设计与实现方案。

---

## 1. 一句话定位

一只住在桌面上的像素小宠物，帮你把计划摆在眼前——你说一句话，它就把计划改好。

## 2. 目标用户

**v1 是自用工具**，没有商业化目标，将来最多打磨成一个开源小工具。第一个、也是最重要的用户是作者本人：

个人电脑的重度使用者，日常有十几条零散待办，但打不开也记不住独立的 to-do App。

核心痛点不是「没有工具记」，而是**记了之后再也没打开过**。

## 3. 为什么是桌宠

普通 to-do App 的失败模式是「打开率归零」。桌宠形态解决的正是这一点：它一直在屏幕上，不需要用户主动想起来去打开它。

- **待办展示**是它存在的价值；
- **趣味性和陪伴感**是用户愿意把它留在桌面上的理由。

## 4. 平台与版本范围

- v1 只支持 **Windows**。mac 版在后续版本提供。
- 界面语言只有**简体中文**；时间一律使用系统本地时区。
- **开机自启**：v1 提供，**默认关闭**。首次启动时询问一次是否开启，之后可在设置页修改。
  - 理由：不自启的话，每次重启后都要用户自己想起来打开 Roost——这正是第 3 节要解决的失败模式。
- **分发**：通过 GitHub Release 提供安装包。v1 不做代码签名，不做自动更新。
  - 后果：首次安装时 Windows 可能提示「已保护你的电脑」，需要手动选择「仍要运行」。
- 同一时间只允许运行一个 Roost；重复启动时，唤出已在运行的那一个。

---

## 5. 核心场景

1. **早上看今天** —— 开机后 Roost 已自动启动（开启自启时），宠物旁边的迷你清单已经列着所有未完成的待办，不需要任何操作；想聚焦时勾选「只显示今日」。
2. **随手加一条** —— 开会中途想起一件事，按下快捷键，敲一句「明天下午三点有个复盘会，很重要」，宠物把它加进明天的计划并打上星标，用户确认一下就完事。
3. **到点被提醒** —— 复盘会开始前 10 分钟，宠物做一个动作并冒个泡提醒，而不是弹一个和系统通知一样冷冰冰的框。

## 6. 产品形态

### 6.1 桌面上的样子

- 桌面上是「**一只宠物 + 紧挨着的迷你清单**」，没有窗口边框，背景透明，始终显示在其他窗口之上。
- **宠物周围的空白区域不能挡住桌面**：用户在宠物和清单以外的地方点击，应该像 Roost 不存在一样，能正常点到桌面图标和下层窗口。这一点在多显示器、不同缩放比例下都必须成立。
- 宠物和清单作为一个整体：
  - **可拖动**到屏幕任意位置；
  - **可贴边**：拖到屏幕边缘附近时自动吸附对齐；
  - **可调整整体透明度**，设最低值，避免调到完全看不见后找不回来。
- 位置记忆与找回：
  - 位置在重启后保持；
  - 显示器拔掉、分辨率或缩放比例变化后，如果宠物落在可见区域之外，自动移回主屏幕内；
  - 宠物靠近屏幕右边缘、清单放不下时，清单翻到宠物左侧显示（上下方向同理）。
- 以上几项是核心体验而非细节——常驻形态最大的风险就是「太占地方」，反感的用户会直接卸载。
- 设置页是一个**独立的普通窗口**，不挤在宠物旁边。

### 6.2 托盘与隐藏

宠物窗口没有边框，因此必须有系统托盘图标作为「总开关」：

- 托盘菜单：**显示 / 隐藏宠物**、**设置**、**退出**。
- **一键隐藏快捷键**：随时隐藏 / 显示宠物和清单。用于屏幕共享、投屏等场景——待办是私人内容，常驻置顶意味着共享屏幕时会被别人看到。
- **检测到全屏应用**（看视频、演示、游戏）时，宠物自动隐藏，退出全屏后自动恢复。

### 6.3 与宠物的交互

| 用户动作 / 状态 | 预期效果 |
|---|---|
| 点击宠物 | 折叠 / 展开整个迷你清单 |
| 拖动宠物 | 宠物播放「被拎起」动画，松手后回到原状态 |
| 鼠标悬停在宠物上 | 宠物播放悬停动画，**不弹出任何信息**，避免鼠标扫过时误触 |
| 完成一条待办 | 宠物播放庆祝动画，播完回到待机 |
| 提醒到点 | 宠物进入提醒动画并冒泡，持续到用户响应 |
| AI 正在处理 | 宠物播放思考动画，直到出预览或失败 |
| AI 没听懂 / 失败 | 宠物冒泡说明原因（不需要单独的动画） |
| 无操作 | 宠物播放待机动画 |

- **点击与拖动的区分**：按下后移动超过几个像素算拖动，否则算点击。
- 待机动画是用户看得最多的状态，它决定了「这只宠物活着还是一张贴图」，质量优先级最高。
- 多个状态同时发生时，优先级：**拖动 > 提醒 > 思考 > 庆祝 > 悬停 > 待机**。
- 宠物共需 **6 种动画**：待机、悬停、拖动、庆祝、提醒、思考。

### 6.4 像素风格的视觉要求

- 宠物是像素风。宠物可以在几档尺寸之间缩放，**任何一档下像素边缘都必须清晰锐利**，不能出现模糊或毛边。这一点在不同的系统缩放比例（100% / 125% / 150% 等）下都必须成立。
- 动画是逐帧切换的像素动画，不做帧间的平滑过渡。

### 6.5 形象

- v1 **只提供内置形象**，不支持用户上传。
- v1 的内置形象**先使用开源或商用授权素材占位**，不等原创美术。
  - 素材必须覆盖 6.3 节的全部 6 种动画，且风格统一。能同时满足这两点的开源素材不多，**选型是排期风险**，需在开工第一阶段完成（见第 19 节）。
  - 发布前**每一个素材都必须核对授权**：来源、许可证、是否允许再分发、是否需要署名，并保存许可证页面快照。需要署名的，署名必须出现在应用的「关于」页和开源仓库中，文本与许可证要求一致。
  - 占位形象没有辨识度。如果将来要对外推广，必须先换成原创形象。

### 6.6 首次启动

- 询问是否开启开机自启（见第 4 节）。
- 清单为空时不显示空白框，而是一条引导：告诉用户点「+」新建待办、点宠物可以折叠清单、在哪里配置 AI。
- 不强制配置模型；不配置也能完整使用本地待办。

## 7. 待办

### 7.1 待办本身

- 新建 / 编辑 / 删除待办。
- 每条待办有：**标题**、**备注**（可空）、**日期与时刻**（可空，即无期限待办）、**星标**（有 / 无）。
- 支持「**只有日期、没有具体时刻**」的待办（如「明天交报告」），和「有具体时刻」的待办（如「明天下午三点开会」）在展示和提醒上区别对待。
- **完成状态是二元对勾**，没有百分比进度。「做了一半」这类状态在 v1 无法表达，用户只能写进备注。
- **星标**表示「重要」，只有有和无两种状态，没有分级。

### 7.2 手动新建与编辑

手动操作和 AI 是**两个独立的入口**：

- 清单上有一个「**+**」按钮，打开新建表单：标题（必填）、日期、时刻、备注、星标。只填标题就能保存，得到一条无期限待办。
- 点击清单中的某一条，打开同一个表单进行编辑。
- 手动新建和编辑**不需要配置模型**，完全离线可用。

### 7.3 迷你清单的显示规则

- **常驻可见**，点击宠物可折叠整个清单。
- **默认显示全部未完成的待办。**
- 每一条显示：标题、星标、时间标签（相对说法，如「今天 15:00」「明天」「已过期 2 天」）。标题过长时截断。
- **「只显示今日」筛选**：清单顶部的一个勾选项。
  - 勾选后显示：截止时间落在「今天」内的待办、已过期但未完成的待办（过期的事仍然是今天要面对的）、**无截止时间但有星标**的待办；
  - 无截止时间、也没有星标的待办不显示；
  - 勾选状态会被记住，重启后保持。
- **排序**：分三组，依次是已过期 → 有截止时间的按时间从早到晚 → 无截止时间的按创建时间倒序（新加的在前）。**每组内星标待办排在前面**，星标之间仍按本组规则排序。
- **条数过多时折叠**：清单最多直接展示 **5** 条（实测后可调），超出部分收成一行「还有 X 条」，点击展开、再点收起。这是清单内部的折叠，和「点击宠物折叠整个清单」是两件事。清单内折叠是必需功能，不是打磨项：默认显示全部会让清单变长，和「太占地方」的风险叠加。
- 已完成和已删除的待办，v1 不提供查看界面，但数据不丢失。

### 7.4 「点对勾」与「删除」

两种不同的行为，界面上位置分开、样式区分，避免把「做完了」误操作成「删掉了」。

| 行为 | 是否需要确认 | 预期效果 |
|---|---|---|
| 点对勾 | 不需要 | 条目划线、宠物播放庆祝动画，几秒后移出清单；移出之前再点一次可取消勾选 |
| 删除 | 不需要 | 条目消失，短暂显示「撤销」入口 |

以上仅指**用户手动操作**。AI 产生的任何变更都必须确认（见第 8 节）。

### 7.5 「今天」与「过期」的定义

- 「今天」的边界由用户设定的**一天起点**决定，默认 **04:00** 而不是 00:00——凌晨两点还在干活的人，心理上仍属于前一天。
- 「只显示今日」筛选、AI 理解「今天 / 明天」、提醒时机，必须使用**同一个定义**，结果不能互相矛盾。
- **过期**：
  - 有具体时刻的待办，过了该时刻即过期；
  - 只有日期的待办，过了那一天（即下一个一天起点）才算过期。

## 8. AI 改计划

### 8.1 能力

用户用一句自然语言描述，AI 把它变成对待办的操作：

- 新增待办（带时间 / 不带时间）
- 修改待办（标题、备注、时间）
- 标记完成 / 取消完成
- 设置 / 取消星标（如「很重要」「这个不急了」）
- 删除待办
- 一句话里可以包含多个操作

### 8.2 输入方式与入口

- v1 **只支持文字输入**。语音移到 v1.1（见第 16 节）。
- 入口：清单上常驻一个「**跟宠物说**」输入框；另有**全局快捷键**，在任何地方按下都能唤出宠物并让输入框获得焦点。
- 没有配置模型时，输入框保留，显示为「配置模型后可用」，点击跳转设置页。

### 8.3 时间理解

- 「明天」「下周三」「后天下午」等相对说法，必须被理解成**具体的日期和时间**，并在预览里明确展示出来让用户核对。
- 只说了日期没说时刻的（「明天交报告」），记为只有日期的待办。
- 「今天 / 明天」按 7.5 节的一天起点计算。例如凌晨 01:00 说「明天」，指的是日历上的当天。
- 解析出的时间**早于当前时刻**时，预览中对该条标出警示（例如凌晨 1 点说「今天下午三点」，按定义会落在已经过去的时间）。

### 8.4 变更预览与确认（强制，不可绕过）

AI 给出的任何改动**都不会直接生效**：

1. 先把所有改动整理成**人话摘要**，例如「新增 1 条：明天 15:00 复盘会 ★；修改 1 条：周报截止时间改到周五」；
2. **删除操作在预览中最醒目地标出**；
3. 每条改动前有勾选框，默认全选，用户可以**逐条去掉**不想要的改动（不支持在预览里修改内容）；
4. 用户点「确认」，勾选的改动才生效；点「取消」则全部丢弃；
5. 确认后，短暂显示「**撤销这次改动**」入口，点击后本次所有改动一起还原。

**理由**：用户自己选择模型，我们无法保证模型质量——便宜的小模型可能误解「把周报删掉那句话不算」这类表述。**模型误删用户攒了两周的计划是不可挽回的失败**，而多点一次确认的成本极低。

将来即使放宽，也只放宽到「纯新增操作可以设置为免确认」，**删除和批量修改永远需要确认**。「批量修改」指一次涉及 2 条及以上已有待办的修改。

### 8.5 单轮，没有追问

- 每次输入独立处理，AI 不会反问用户。
- 表述模糊或无法理解时，**不猜、不产生任何改动**，宠物提示没听懂，用户重新输入。
- **一句话能对应到多条待办时**（例如「把会改到四点」，而清单里有两个会），视为无法确定：不产生任何改动，并告诉用户匹配到了哪几条，请用户说得更具体。
- 失败后，原文保留在输入框里，改完可直接再发。
- 代价：一句话说得含糊时，用户得整句重说，而不是只补一个细节。

### 8.6 AI 不能犯的错

- 用户说「做完了」时，**不能**被理解成删除。
- 用户没有提到的待办，**不能**被改动。
- 对不存在的待办的操作，在预览中标为无效，不会生效。

**AI 评测集**：把上面的规则和 8.1–8.5 的能力整理成 50–100 句测试语料，每句写明期望结果。每个快捷预设推荐的模型都必须跑过评测集：本节三类错误**一次都不能出现**，其余语料正确率 ≥ 90%。达不到的模型不能放进预设。

### 8.7 发送给模型的内容

- AI 要修改已有待办，就必须看到待办列表。发送范围：**全部未完成的待办** + **最近 7 天内完成的待办**（用于「取消完成」）。已删除的待办不发送。
- 发送范围不随使用时长增长，这也是 9.5 节费用可控的前提。

### 8.8 等待与失败

- 请求发出后，宠物进入思考动画，输入框旁可**取消**本次请求。
- 超过一定时间没有返回按超时处理（具体时长由设计确定）。

| 情况 | 预期效果 |
|---|---|
| 没有配置模型 | 引导去设置页，同时说明「不配置也能正常使用本地待办」 |
| key 无效 | 明确告诉用户是 key 的问题，给出去设置页的入口 |
| 网络失败 / 超时 | 提示可重试，**用户输入的原文必须保留**，不能让人重说一遍 |
| AI 没听懂 / 返回无法理解 | 把模型的文字回复原样展示给用户（过长时截断），不假装成功 |

**总原则：任何 AI 相关的失败都不能影响本地待办的正常使用。** 没有 key、断网、模型挂掉，Roost 都还是一个完整可用的本地待办工具。

## 9. 模型配置（用户自带 key）

### 9.1 模式

- AI 功能使用**用户自己的模型服务账号和 API Key**，我们不提供模型服务、不收费。
- 用户可以对隐私做出诚实的判断：**「你的 key、你的账单，数据不经过我们」**。
- 支持主流的 OpenAI 兼容模型服务。用户填写服务地址、key 和模型名。

### 9.2 快捷预设

- 提供以下厂商的快捷预设：**DeepSeek、通义千问、Kimi、智谱、豆包**。
- 选择预设后自动填好服务地址和推荐的模型名，用户只需要填 key。
- 每个预设附一句话说明和「去申请 key」的链接。不做分步图文教程。
- 预设的推荐模型必须通过 8.6 节的 AI 评测集。

### 9.3 保存配置时立即检测

用户保存配置后，产品**立即**检测 key、服务地址和模型名是否有效，并当场给出结果。不能等到用户第一次改计划时才报错。

### 9.4 隐私告知

**首次保存模型配置时**，明确告诉用户：「改计划时，你的待办内容会发送给你选择的模型厂商。」用户确认后才保存。只告知一次。

### 9.5 费用

AI 调用的费用由用户承担，因此单次调用的成本应当可控，**不应随用户使用时长的增加而明显变贵**（见 8.7 节）。

## 10. 提醒

### 10.1 什么时候提醒

- 提醒由待办的时间决定，没有单独的「提醒」对象。无期限待办不提醒。
- **有具体时刻的待办**：提前 X 分钟提醒。X 在设置页全局设置，可选 0 / 5 / 10 / 15 / 30，默认 **10**。
- **只有日期的待办**：当天 **09:00** 提醒，时刻可在设置页修改。

### 10.2 提醒的样子

- 到点时，**宠物冒泡 + 系统通知**。
- 冒泡里有三个操作：
  - **完成**：等同于点对勾，宠物播放庆祝动画；
  - **稍后提醒**：可选 10 分钟 / 1 小时；
  - **知道了**：关闭提醒，待办保持不变。
- 多条同时到点时，冒泡合并显示为「有 X 件事到点了」，展开后逐条处理。

### 10.3 不打扰

- 全屏或免打扰状态下**不弹系统通知**（否则用户会在第一次开会被打断后就把提醒关掉），事后也不补发。
- 宠物的提醒冒泡会一直保持到用户响应，所以退出全屏、宠物重新出现后，用户仍然能看到它。

### 10.4 错过的提醒

- Roost 没有运行、电脑休眠期间到点的提醒，下次启动或唤醒时**不逐条补弹**。
- 如果有错过的提醒，宠物冒一个汇总泡：「你不在的时候有 X 件事到点了」。对应的待办已经按过期规则排在清单最前面。

## 11. 数据与隐私

- **所有数据只存在本机**，没有账号，不做多端同步，离线完全可用。
  - 后果：换电脑数据不跟随，重装系统前用户需要自己备份，也做不到「在手机上看今天的待办」。
- **数据安全**：程序崩溃、强制结束或断电时，已经保存的数据不能损坏或丢失。自动保留**最近 7 份**本地备份。
- **数据导出为 JSON 文件**，这是「纯本地」的强制配套，不是可选功能，否则用户会觉得数据被锁死。
  - 导出包含全部未删除的待办（含已完成的），附带导出时间与格式版本；
  - 导出格式必须能被将来重新导入——v1 不做导入界面，但不能让「导出」只是心理安慰。
- 删除都是可恢复的（软删除），不会真正抹掉数据。
- **API Key 必须安全保存**：使用系统提供的安全存储，不以明文形式出现在任何文件或日志里。
- **待办内容是私人内容**：不得出现在任何日志里。
- 不收集任何使用统计，不上报任何数据。

## 12. 设置页

- 模型配置：服务地址、key、模型名，快捷预设，保存时自动检测，首次保存时的隐私告知（见第 9 节）。
- 外观：宠物尺寸档位、整体透明度等。
- 提醒：有时刻待办提前几分钟、只有日期的待办几点提醒、是否弹系统通知。
- 快捷键：唤出「跟宠物说」输入框、一键隐藏。可修改，与其他软件冲突时给出提示。
- 开机自启开关。
- 一天起点（默认 04:00）。
- 数据导出。
- 关于页：版本号、开源仓库地址、素材署名。

## 13. 性能与体积预期

桌宠是 24 小时挂在桌面上的常驻程序，**体积和资源占用直接决定用户会不会把它留下**，是产品卖点而不是技术细节。

| 指标 | 预期 |
|---|---|
| 安装包 | 约 8–15MB，超出需说明原因 |
| 常驻内存 | 约 60–100MB |
| 待机时 CPU | 待机动画正常播放时，平均 CPU ≤ 0.5%（在作者本人的电脑上测量）。常驻程序持续 1% 的占用，用户会在任务管理器里看到 |
| 冷启动时间 | 上线前实测 |

- 宠物被隐藏、处于全屏应用下、屏幕锁定时，动画**暂停**，不消耗资源。

## 14. v1 明确不做的事

| 不做 | 理由 |
|---|---|
| 语音输入 | 移到 v1.1。供应商能力尚未验证；v1 先把文字路径做好 |
| 重复任务（每天 / 每周） | 重复规则 + 单次例外（这周跳过、只改这一次）比看起来复杂得多，约多一周工作量。「每天喝水」这类需求在 v1 只能每天手动添加 |
| 用户上传图片转像素风 | 这是产品最大的传播点，也是质量最不可控的一环。先把「桌宠 + 待办 + AI 改计划」主线跑通 |
| 账号与多端同步 | 自用工具，不值得背运维负担 |
| mac 版 | 先集中验证 Windows |
| 唤醒词 / 常开麦克风 | 隐私观感极差且持续耗电 |
| 百分比进度 | 进度只有二元对勾 |
| 重要性分级 | 只有星标的有 / 无 |
| AI 追问 / 多轮对话 | 解析失败让用户重新输入即可 |
| 在 AI 预览里修改内容 | 只能逐条去勾；要改内容就重新说 |
| 悬停时宠物看向鼠标 | v1 的悬停只是一个循环动画 |
| 查看已完成 / 已删除的待办 | 数据保留，界面后续再做 |
| 代码签名、自动更新 | 自用和小范围开源分发，成本不值得 |
| 分厂商图文教程 | 用预设 + 一句话说明 + 申请链接代替 |
| 使用统计 / 数据上报 | 自用工具，不需要，也与「数据不经过我们」冲突 |
| 番茄钟、习惯打卡、日历同步等扩展玩法 | 属于 v1 之后的方向，现在做会稀释核心场景 |

## 16. 后续版本方向

- **v1.1：语音输入。**
  - 用户主动触发录音（不做唤醒词、不常开麦克风），录完走与文字相同的预览确认流程；
  - 保存模型配置时立即检测是否支持语音，不支持时当场提示并在设置页标记。**绝不能等用户对着麦克风说完一段话才报错**；
  - 开工前先做供应商验证，并定下可接受的等待时长和识别成功率，达不到就不做。
- **v2：用户上传图片，自动转换成像素风桌宠。** 转出来的形象要和内置形象达到同样的标准：像素清晰、6 种动画状态齐全、边缘干净无毛边。达不到就不能上桌面。
- mac 版。
- 纯新增类 AI 操作可设置为免确认（删除和批量修改除外）。
- 如果实际使用中觉得「太占地方」，评估改为默认折叠、只显示一个计数气泡。

## 18. 优先级与验收标准

### 18.1 优先级

**P0**：缺了 v1 就不成立，排期紧张时最后砍。

- 透明窗口、空白处点击穿透（多显示器、多缩放比例）
- 拖动、贴边、透明度、位置记忆与找回
- 托盘菜单、一键隐藏
- 待机 / 悬停 / 庆祝 / 提醒动画，像素清晰
- 手动新建 / 编辑 / 完成 / 删除（含撤销）、星标
- 清单显示、排序、只显示今日、清单内折叠
- AI 文字改计划：预览、确认、删除醒目标出、失败时保留原文
- 提醒：冒泡 + 系统通知、稍后提醒、全屏 / 免打扰时不弹通知
- 数据安全与自动备份、API Key 安全保存
- 数据导出

**P1**：体验明显变差，但 v1 仍然成立。

- 拖动、思考动画（缺失时用待机动画代替）
- AI 预览逐条去勾、确认后撤销、过去时间警示
- 检测到全屏应用时自动隐藏
- 开机自启
- 首次启动引导
- 错过提醒的汇总泡
- 快捷键可修改

### 18.2 验收标准

| 模块 | 验收标准 |
|---|---|
| 点击穿透 | 两块显示器、100% / 150% 缩放组合下，宠物和清单以外的任意位置点击都能落到下层窗口 |
| 像素清晰 | 每一档尺寸、每一种缩放比例下截图放大检查，没有模糊或半透明的边缘像素 |
| 资源占用 | 待机 1 小时，平均 CPU ≤ 0.5%，内存在第 13 节范围内 |
| 日期规则 | 一天起点边界前后（03:59 / 04:00）的「今日」筛选、「今天 / 明天」解析、过期判断三者结果一致 |
| AI | 所有预设推荐模型通过 8.6 节评测集 |
| AI 确认 | 任何路径下，AI 的改动都不能在用户点确认之前生效 |
| 离线 | 断网、未配置 key 时，除 AI 外的全部功能正常 |
| 数据安全 | 写入过程中强制结束进程，重启后数据完整 |
| 隐私 | 检查全部日志文件，不含待办内容和 API Key |
| 导出 | 导出的 JSON 包含全部未删除待办及格式版本字段 |
