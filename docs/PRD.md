# Roost 产品需求文档（v1）

> 相关文档：决策与理由见 [DECISIONS.md](./DECISIONS.md)，技术方案见 [ARCHITECTURE.md](./ARCHITECTURE.md)，排期见 [MILESTONES.md](./MILESTONES.md)。

## 一句话定位

一只住在桌面上的像素小宠物，帮你把计划摆在眼前——你说一句话，它就把计划改好。

## 目标用户

个人电脑的重度使用者，日常有十几条零散待办，但打不开也记不住独立的 to-do App。核心痛点不是「没有工具记」，而是**记了之后再也没打开过**。

## 为什么是桌宠

普通 to-do App 的失败模式是「打开率归零」。桌宠形态解决的正是这一点：它一直在屏幕上，不需要用户主动想起来去打开它。趣味性和陪伴感是留住它的理由，待办展示是它存在的价值。

---

## 核心场景

1. **早上看今天** —— 开机后宠物旁边的迷你清单已经列着今天和未来要做的待办事项，不需要任何操作。
2. **随手加一条** —— 开会中途想起一件事，对着宠物说「我明天下午三点有个复盘会，很重要」，宠物把它加进明天的计划，用户确认一下就完事。
3. **到点被提醒** —— 截止时间到了，宠物做一个动作并冒个泡提醒，而不是弹一个和系统通知一样冷冰冰的框。

---

## 形态定义

- 一个**透明、无边框、置顶**的窗口，里面是「宠物 + 紧挨着的迷你清单」。
- **迷你清单常驻可见**，可折叠。点击宠物 = 折叠 / 展开。（决策与代价见 D7）
- **鼠标悬停不弹任何信息**，只做表情反馈：宠物看向鼠标、做个小动作。避免鼠标扫过时误触弹窗。
- 窗口可拖动、可贴边、可调整整体透明度。这几项是核心体验而非细节——常驻形态的最大风险就是「太占地方」。
- 透明区域必须能点到桌面图标（点击穿透，见 `ARCHITECTURE.md`）。
- 设置页是一个独立的普通窗口，不挤在宠物旁边。

## v1 功能清单

### 待办本体
- 新建 / 编辑 / 删除待办
- 标题、备注、**日期与截止时间**
- **进度二分对勾**
- 视图：所有尚未完成的待办事项

### AI 改计划
- **文字自然语言输入**（保底路径，所有模型可用）：输入「明天有个会很重要」→ 解析成待办变更
- **语音输入**：录一段话直接送多模态模型（依赖 M0 spike 结论，见 D8）
- **所有 AI 产生的变更必须先预览、用户确认后才落库**。理由见 `AI-PIPELINE.md`——BYOK 下我们无法保证模型质量，模型误删用户计划是不可接受的失败。

### 提醒
- 到点通过宠物冒泡 + 系统通知提醒
- 支持稍后提醒
- 全屏 / 免打扰状态下不弹（否则用户会在第一次开会被打断后就把提醒关掉）

### 其他
- 数据导出为 JSON（D4 的强制配套，不是可选功能）
- 设置页：模型配置（base_url / key / model）+ 能力探测、外观、提醒偏好

## v1 明确不做的事

> **写在这里是为了防止后续 session 的 Agent「顺手补上」。要做其中任何一项，先按 `CLAUDE.md` 的规范提案。**

| 不做 | 推迟理由 |
|---|---|
| 重复任务（每天 / 每周） | 重复规则 + 单次例外（这周跳过、只改这一次）的数据模型比看起来复杂，约多一周工作量。v1 先验证主线。 |
| 用户上传图片转像素风 | 见 D2。质量最不可控的一环，主线跑通后再做，sprite 规格已提前定死以便无痛接入。 |
| 账号与多端同步 | 见 D4。会把 v1 上线推后至少一个月，且在「桌宠好不好玩」还没验证时就背上运维负担。 |
| 开机自启 | 用户明确表示后续再实现。技术上不难，但涉及安装器和用户信任，放到形态稳定后再做。 |
| mac 版 | 先集中验证 Windows。Tauri 的选型已经保证了将来不用重写（D1）。 |
| 唤醒词 / 常听麦克风 | 隐私观感极差且持续耗电。语音一律由用户主动触发。 |
| 番茄钟、习惯打卡、日历同步等扩展玩法 | 属于 v1 之后的方向，现在做会稀释核心场景。 |

---

## v1 的成功标准

不是装机量，而是：**装了一周后还留在桌面上，且期间至少用 AI 改过一次计划。** 这两件事同时成立，才说明「桌宠形态」和「一句话改计划」两个赌注都成立。
