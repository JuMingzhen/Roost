# Roost 产品需求文档（v1）

> 本文只描述需求和预期效果，不涉及设计与实现方案。

---

## 1. 一句话定位

一只住在桌面上的像素小宠物，帮你把计划摆在眼前——你说一句话，它就把计划改好。

## 2. 目标用户

个人电脑的重度使用者，日常有十几条零散待办，但打不开也记不住独立的 to-do App。

核心痛点不是「没有工具记」，而是**记了之后再也没打开过**。

## 3. 为什么是桌宠

普通 to-do App 的失败模式是「打开率归零」。桌宠形态解决的正是这一点：它一直在屏幕上，不需要用户主动想起来去打开它。

- **待办展示**是它存在的价值；
- **趣味性和陪伴感**是用户愿意把它留在桌面上的理由。

## 4. 平台与版本范围

- v1 只支持 **Windows**。mac 版在后续版本提供。
- v1 **不做开机自启**，用户需手动启动。

---

## 5. 核心场景

1. **早上看今天** —— 启动 Roost 后，宠物旁边的迷你清单已经列着所有未完成的待办，不需要任何操作；想聚焦时勾选「只显示今日」。
2. **随手加一条** —— 开会中途想起一件事，对着宠物说「我明天下午三点有个复盘会，很重要」，宠物把它加进明天的计划，用户确认一下就完事。
3. **到点被提醒** —— 截止时间到了，宠物做一个动作并冒个泡提醒，而不是弹一个和系统通知一样冷冰冰的框。

---

## 6. 产品形态

### 6.1 桌面上的样子

- 桌面上是「**一只宠物 + 紧挨着的迷你清单**」，没有窗口边框，背景透明，始终显示在其他窗口之上。
- **宠物周围的空白区域不能挡住桌面**：用户在宠物和清单以外的地方点击，应该像 Roost 不存在一样，能正常点到桌面图标和下层窗口。这一点在多显示器、不同缩放比例下都必须成立。
- 宠物和清单作为一个整体：
  - **可拖动**到屏幕任意位置；
  - **可贴边**；
  - **可调整整体透明度**。
- 以上几项是核心体验而非细节——常驻形态最大的风险就是「太占地方」，反感的用户会直接卸载。
- 设置页是一个**独立的普通窗口**，不挤在宠物旁边。

### 6.2 与宠物的交互

| 用户动作 | 预期效果 |
|---|---|
| 点击宠物 | 折叠 / 展开整个迷你清单 |
| 鼠标悬停在宠物上 | 宠物播放悬停动画，**不弹出任何信息**，避免鼠标扫过时误触 |
| 完成一条待办 | 宠物播放庆祝动画，播完回到待机 |
| 提醒到点 | 宠物进入提醒动画并冒泡，持续到用户响应 |
| 无操作 | 宠物播放待机动画 |

- 待机动画是用户看得最多的状态，它决定了「这只宠物活着还是一张贴图」，质量优先级最高。
- 多个状态同时发生时，优先级：**提醒 > 庆祝 > 悬停 > 待机**。

### 6.3 像素风格的视觉要求

- 宠物是像素风。宠物可以在几档尺寸之间缩放，**任何一档下像素边缘都必须清晰锐利**，不能出现模糊或毛边。
- 动画是逐帧切换的像素动画，不做帧间的平滑过渡。

### 6.4 形象

- v1 **只提供内置形象**，不支持用户上传。
- v1 的内置形象**先使用开源或商用授权素材占位**，不等原创美术。
  - 后果：v1 形象没有辨识度，不能作为品牌资产对外宣传。
  - 上线前**每一个素材都必须核对授权**：来源、许可证、是否允许商用、是否需要署名，并保存许可证页面快照。需要署名的，署名必须出现在应用的「关于」页，文本与许可证要求一致。
  - 正式推广前，必须先用一套原创形象替换占位素材。

## 7. 待办

### 7.1 待办本身

- 新建 / 编辑 / 删除待办。
- 每条待办有：**标题**、**备注**（可空）、**日期与截止时间**（可空，即无期限待办）。
- 支持「**只有日期、没有具体时刻**」的待办（如「明天交报告」），和「有具体时刻」的待办（如「明天下午三点开会」）在展示和提醒上区别对待。
- **完成状态是二元对勾**，没有百分比进度。「做了一半」这类状态在 v1 无法表达，用户只能写进备注。

### 7.2 迷你清单的显示规则

- **常驻可见**，点击宠物可折叠整个清单。
- **默认显示全部未完成的待办。**
- **「只显示今日」筛选**：清单顶部的一个勾选项。
  - 勾选后只显示截止时间落在「今天」内的待办，以及已过期但未完成的待办（过期的事仍然是今天要面对的）；
  - 无截止时间的待办不显示；
  - 勾选状态会被记住，重启后保持。
- **排序**：已过期 → 有截止时间的按时间从早到晚 → 无截止时间的按创建时间倒序（新加的在前）。
- **条数过多时折叠**：清单最多直接展示 N 条，超出部分收成一行「还有 X 条」，点击展开、再点收起。这是清单内部的折叠，和「点击宠物折叠整个清单」是两件事。清单内折叠是必需功能，不是打磨项：默认显示全部会让清单变长，和「太占地方」的风险叠加。
- 已完成和已删除的待办，v1 不提供查看界面，但数据不丢失。

### 7.3 「点对勾」与「删除」

两种不同的行为，界面上位置分开、样式区分，避免把「做完了」误操作成「删掉了」。

| 行为 | 是否需要确认 | 预期效果 |
|---|---|---|
| 点对勾 | 不需要 | 条目划线、宠物播放庆祝动画，几秒后移出清单；移出之前再点一次可取消勾选 |
| 删除 | 不需要 | 条目消失，短暂显示「撤销」入口 |

以上仅指**用户手动操作**。AI 产生的任何变更都必须确认（见第 8 节）。

### 7.4 「今天」的定义

- 「今天」的边界由用户设定的**一天起点**决定，默认 **04:00** 而不是 00:00——凌晨两点还在干活的人，心理上仍属于前一天。
- 「只显示今日」筛选和 AI 理解「今天 / 明天」时，必须使用**同一个定义**，两边结果不能不一致。

## 8. AI 改计划

### 8.1 能力

用户用一句自然语言描述，AI 把它变成对待办的操作：

- 新增待办（带时间 / 不带时间）
- 修改待办（标题、备注、时间）
- 标记完成 / 取消完成
- 删除待办
- 一句话里可以包含多个操作

### 8.2 两种输入方式

| 输入方式 | 可用性 | 说明 |
|---|---|---|
| **文字** | 所有模型都可用，**保底路径** | 用户敲一句话 |
| **语音** | 仅限支持语音输入的模型 | 用户主动触发录音说一段话。能否实现、效果如何，取决于开工前的供应商验证结论 |

- 产品的 AI 能力**不能只挂在语音上**，文字路径必须先做完、先做好。
- 语音**一律由用户主动触发**，不做唤醒词，不常开麦克风。

### 8.3 时间理解

- 「明天」「下周三」「后天下午」等相对说法，必须被理解成**具体的日期和时间**，并在预览里明确展示出来让用户核对。
- 只说了日期没说时刻的（「明天交报告」），记为只有日期的待办。

### 8.4 变更预览与确认（强制，不可绕过）

AI 给出的任何改动**都不会直接生效**：

1. 先把所有改动整理成**人话摘要**，例如「新增 1 条：明天 15:00 复盘会；修改 1 条：周报截止时间改到周五」；
2. **删除操作在预览中最醒目地标出**；
3. 用户点「确认」才生效；点「取消」则全部丢弃。

**理由**：用户自己选择模型，我们无法保证模型质量——便宜的小模型可能误解「把周报删掉那句话不算」这类表述。**模型误删用户攒了两周的计划是不可挽回的失败**，而多点一次确认的成本极低。

将来即使放宽，也只放宽到「纯新增操作可以设置为免确认」，**删除和批量修改永远需要确认**。

### 8.5 单轮，没有追问

- 每次输入独立处理，AI 不会反问用户。
- 表述模糊或无法理解时，**不猜、不产生任何改动**，宠物提示没听懂，用户重新说或重新输入。
- 文字输入失败后，原文保留在输入框里，改完可直接再发。
- 代价：一句话说得含糊时，用户得整句重说，而不是只补一个细节。

### 8.6 AI 不能犯的错

- 用户说「做完了」时，**不能**被理解成删除。
- 用户没有提到的待办，**不能**被改动。
- 对不存在的待办的操作，在预览中标为无效，不会生效。

### 8.7 失败时用户看到什么

| 情况 | 预期效果 |
|---|---|
| 没有配置模型 | 引导去设置页，同时说明「不配置也能正常使用本地待办」 |
| key 无效 | 明确告诉用户是 key 的问题，给出去设置页的入口 |
| 网络失败 / 超时 | 提示可重试，**用户输入的原文必须保留**，不能让人重说一遍 |
| 模型不支持语音 | 在设置页就已经提示过；若仍发生，提示改用文字输入 |
| AI 没听懂 / 返回无法理解 | 把模型的文字回复原样展示给用户，不假装成功 |

**总原则：任何 AI 相关的失败都不能影响本地待办的正常使用。** 没有 key、断网、模型挂掉，Roost 都还是一个完整可用的本地待办工具。

## 9. 模型配置（用户自带 key）

### 9.1 模式

- 语音和 AI 功能使用**用户自己的模型服务账号和 API Key**，我们不提供模型服务、不收费。
- 用户可以对隐私做出诚实的判断：**「你的 key、你的账单，数据不经过我们」**。
- 支持主流的 OpenAI 兼容模型服务。用户填写服务地址、key 和模型名，界面提供几个常见厂商的快捷预设，并**标注哪些支持语音**。

### 9.2 代价与强制配套

- 普通用户不知道 API Key 是什么，这会把 AI 功能的上手门槛抬到开发者水平，非技术用户很可能在设置页流失。
- 因此**设置页的引导质量是产品成败项，不是打磨项**：必须有分厂商的图文步骤，而不是一个空的输入框。
- 没有 key 时，产品仍然是一个完整可用的本地待办工具。

### 9.3 保存配置时立即检测

用户保存配置后，产品**立即**检测：

1. key 和服务地址是否有效；
2. 该模型是否支持语音输入。

不支持语音时**当场**提示「该模型不支持语音输入，你仍可以用文字改计划」，并在设置页标记语音不可用。

**绝不能等用户对着麦克风说完一段话才报错**——那是整个产品里最糟糕的失败时机。

### 9.4 费用

AI 调用的费用由用户承担，因此单次调用的成本应当可控，**不应随用户使用时长的增加而明显变贵**。

## 10. 提醒

- 到点时，**宠物冒泡 + 系统通知**。
- 支持**稍后提醒**。
- 全屏或免打扰状态下**不弹**（否则用户会在第一次开会被打断后就把提醒关掉）。

---

## 11. 数据与隐私

- **所有数据只存在本机**，没有账号，不做多端同步，离线完全可用。
  - 后果：换电脑数据不跟随，重装系统前用户需要自己备份，也做不到「在手机上看今天的待办」。
- **数据导出为 JSON 文件**，这是「纯本地」的强制配套，不是可选功能，否则用户会觉得数据被锁死。
  - 导出包含全部未删除的待办（含已完成的）和提醒，附带导出时间与格式版本；
  - 导出格式必须能被将来重新导入——v1 不做导入界面，但不能让「导出」只是心理安慰。
- 删除都是可恢复的（软删除），不会真正抹掉数据。
- **API Key 必须安全保存**：使用系统提供的安全存储，不以明文形式出现在任何文件或日志里。
- **待办内容是私人内容**：不得出现在任何日志或错误上报里。

## 12. 设置页

- 模型配置：服务地址、key、模型名，常见厂商快捷预设与图文引导，保存时自动检测（见第 9 节）。
- 外观：宠物尺寸档位、整体透明度等。
- 提醒偏好。
- 一天起点（默认 04:00）。
- 数据导出。
- 关于页：含素材署名。

## 13. 性能与体积预期

桌宠是 24 小时挂在桌面上的常驻程序，**体积和资源占用直接决定用户会不会把它留下**，是产品卖点而不是技术细节。

| 指标 | 预期 |
|---|---|
| 安装包 | 约 8–15MB，超出需说明原因 |
| 常驻内存 | 约 60–100MB |
| 空闲时 CPU | 接近 0。常驻程序持续 1% 的占用，用户会在任务管理器里看到 |
| 冷启动时间 | 上线前实测 |

## 14. v1 明确不做的事

| 不做 | 理由 |
|---|---|
| 重复任务（每天 / 每周） | 重复规则 + 单次例外（这周跳过、只改这一次）比看起来复杂得多，约多一周工作量。「每天喝水」这类需求在 v1 只能每天手动添加 |
| 用户上传图片转像素风 | 这是产品最大的传播点，也是质量最不可控的一环。先把「桌宠 + 待办 + 语音改计划」主线跑通 |
| 账号与多端同步 | 会把上线推后至少一个月，且在「桌宠好不好玩」还没验证时就背上运维负担 |
| 开机自启 | 涉及安装器和用户信任，放到形态稳定后再做 |
| mac 版 | 先集中验证 Windows |
| 唤醒词 / 常开麦克风 | 隐私观感极差且持续耗电 |
| 百分比进度 | 进度只有二元对勾 |
| AI 追问 / 多轮对话 | 解析失败让用户重新输入即可 |
| 悬停时宠物看向鼠标 | v1 的悬停只是一个循环动画 |
| 查看已完成 / 已删除的待办 | 数据保留，界面后续再做 |
| 番茄钟、习惯打卡、日历同步等扩展玩法 | 属于 v1 之后的方向，现在做会稀释核心场景 |

---

## 15. 对外宣传的约束

- v1 **不能暗示「上传自家宠物照片生成桌宠」的能力已经存在**。早期用户很可能会问「不是说能传我家猫吗」，对外文案必须提前管理预期。
- v1 的占位形象不能作为主视觉用于推广。

---

## 16. 后续版本方向

- **v2：用户上传图片，自动转换成像素风桌宠。** 转出来的形象要和内置形象达到同样的标准：像素清晰、四种动画状态齐全、边缘干净无毛边。达不到就不能上桌面。
- 开机自启、mac 版。
- 视用户反馈再评估：
  - 如果大量用户卡在配置 key 这一步，评估由我们提供模型服务（需同时接受服务器成本、用量限额、防滥用三项工作量）；
  - 如果用户反馈集中在「太占地方」，评估改为默认折叠、只显示一个计数气泡；
  - 出现明确的多端需求时，评估账号与同步。
- 纯新增类 AI 操作可设置为免确认（删除和批量修改除外）。

---

## 17. v1 的成功标准

不是装机量，而是：

> **装了一周后还留在桌面上，且期间至少用 AI 改过一次计划。**

这两件事同时成立，才说明「桌宠形态」和「一句话改计划」两个赌注都成立。

---

## 18. 待确认事项

- **语音是否可行**：取决于开工前的供应商验证结论；可接受的等待时长和成功率尚未定。
- **清单内折叠的条数 N**：待实测后确定。
- **提醒时机**：准点提醒还是提前提醒；只有日期的待办在几点提醒；全屏 / 免打扰期间被压下的提醒，结束后是否补发。
- **AI 的入口**：文字输入框放在哪里，语音如何触发（按钮 / 按住说话 / 快捷键）。
- **隐私告知**：待办内容会发送给用户自己选择的模型厂商，是否需要在首次配置时明确告知用户。
- **点击与拖动的区分**：点击宠物是折叠清单，拖动宠物是移动位置，两者如何区分。
