# 形象与动画规格

> 前置阅读：[DECISIONS.md](./DECISIONS.md) 的 D2（v1 只做内置形象）、D5（先用授权素材占位）。
>
> **本文定死的规格有一个明确目的**：v2 接「用户上传图片转像素风」时，只要转换产物符合同一规格，就能直接替换进来，渲染层一行不用改。所以规格改动的影响面比看起来大，改之前先想清楚。

---

## Sprite 规格

| 项 | 约定 |
|---|---|
| 单帧尺寸 | 64 × 64 px（源尺寸） |
| 显示缩放 | **只允许整数倍**（2x / 3x / 4x）。非整数倍缩放会让像素边缘出现毛刺，像素风立刻变廉价 |
| 渲染 | CSS 必须设 `image-rendering: pixelated`，禁止任何平滑插值 |
| 格式 | PNG，带 alpha 通道 |
| 组织方式 | 每个状态一张横向 sprite sheet，帧从左到右 |
| 帧率 | 默认 8 fps；单个状态可在配置里覆盖 |
| 调色板 | 每个形象不超过 32 色，全套动画共用同一调色板 |

---

## 状态机

v1 必须提供的四个状态：

| 状态 | 触发 | 循环 | 建议帧数 |
|---|---|---|---|
| `idle` | 默认 | 是 | 4–8 |
| `hover` | 鼠标悬停在宠物上 | 是 | 2–4 |
| `notify` | 到点提醒 | 是（直到用户响应） | 4–6 |
| `celebrate` | 待办完成 | 否，播完回 `idle` | 4–8 |

`idle` 是用户看得最多的状态，它的质量决定了「这只宠物活着还是一张贴图」。做不好的话，其他三个状态再精致也没用。

状态优先级：`notify` > `celebrate` > `hover` > `idle`。

## 文件组织

```
src-tauri/assets/pets/
└── <pet_id>/
    ├── meta.json
    ├── idle.png
    ├── hover.png
    ├── notify.png
    └── celebrate.png
```

`meta.json` 至少包含：`id`、`name`、每个状态的帧数与帧率覆盖、作者与许可证信息。

**许可证信息写进 `meta.json` 而不是只写在文档里**，是为了让它跟着素材走——素材被复制、替换时，授权信息不会掉队。

## 素材授权登记表（D5 的直接后果）

**上线前必须逐条核对。漏一条就是法律风险。**

| pet_id | 来源 / 链接 | 许可证 | 允许商用 | 需要署名 | 署名文本 | 核对人 | 核对日期 |
|---|---|---|---|---|---|---|---|
| _(待填)_ | | | | | | | |

核对要点：

- 「免费下载」不等于「允许商用」，必须看到明确的许可证文本；
- 需要署名的素材，署名必须出现在应用的关于页里，且文本要和许可证要求一致；
- 保存许可证页面的快照，链接会失效；
- 素材文件超过 1MB 入库需单独批准（见 `CLAUDE.md` 的 Git 规范）。

## v2 转换产物的要求（前瞻）

用户上传图片转出来的形象，必须满足：64×64、≤32 色、四个状态齐全、alpha 通道干净（无半透明毛边——半透明像素在整数倍放大后会变成明显的灰边）。

达不到就不能进渲染层。这条要求会反过来约束 v2 的转换管线设计，现在写下来是为了那时不用返工。
