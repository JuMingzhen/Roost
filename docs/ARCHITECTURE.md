# 技术架构

> 前置阅读：[DECISIONS.md](./DECISIONS.md)（尤其 D1、D7）。
> 本文描述的目录结构在 M1 之前是**规划**，代码落地后如有偏差，以代码为准并回来修正本文。

## 技术栈

| 层 | 选型 | 备注 |
|---|---|---|
| 壳 | Tauri v2 | Windows 优先，mac 后续适配（D1） |
| 后端 | Rust | 数据、调度、系统集成、密钥、外部 API 调用 |
| 前端 | TypeScript + Vite | 只负责渲染与交互 |
| 存储 | SQLite | 纯本地，无账号（D4） |

前端框架和状态管理在 M1 开工时确定，选定后写回本表。**不引入 UI 组件库**——桌宠界面高度定制，组件库只会增加体积、带来用不上的样式。

---

## 职责边界（硬规则）

- **Rust 侧**持有：数据库、API Key、所有对外部服务的网络请求、定时调度、窗口与系统集成。
- **Web 侧**只做：渲染、动画、用户交互，通过 Tauri command 与 Rust 通信。
- **Web 侧不得直接持有 API Key，不得直接发起对外部服务的请求。** 前端资源相对容易被提取，key 落到前端等于泄露。这条是安全红线，见 `CLAUDE.md`。

---

## 窗口模型

**一个透明置顶窗口**承载「宠物 + 迷你清单」。

不拆成两个窗口的理由：两者需要严格贴合、一起拖动、共享层级和透明度。拆窗口后，位置同步、Z 序、多显示器切换都会变成持续的 bug 来源。

**设置页是独立的普通窗口**（有边框、可最大化、不置顶），因为它的交互形态和常驻窗口完全不同。

---

## 点击穿透：本项目最大的技术风险

透明窗口默认会吃掉整个矩形区域的鼠标事件。如果不处理，用户会发现宠物周围一大片桌面点不动、图标双击不开——这是会直接导致卸载的问题。

**方案**：Rust 侧用 `set_ignore_cursor_events` 动态开关，前端做命中测试（鼠标是否落在宠物或清单的不透明区域内），状态变化时通知 Rust 切换。

**已知的坑，实现时必须处理**：
- 开启穿透后窗口收不到鼠标事件，无法自己判断鼠标何时移回来——需要 Rust 侧轮询全局光标位置，或用平台级 hook。轮询频率是「响应速度」和「CPU 占用」的直接权衡，常驻程序对后者敏感。
- 鼠标快速划过边界时，穿透状态可能来回抖动，需要加滞后区间（hysteresis）。
- 多显示器 + 不同 DPI 时，物理坐标和逻辑坐标的换算容易出错，必须在双屏不同缩放比的环境下实测。

**M1 的验收标准之一就是这件事在双屏环境下稳定。** 如果做了两周仍不稳定，触发 D1 的复议条件。

## 目录规划

```
Roost/
├── docs/                    # 产品与技术文档（本目录）
├── src/                     # 前端
│   ├── pet/                 # 宠物渲染、sprite 动画、状态机
│   ├── todo/                # 迷你清单、今日视图、编辑交互
│   └── settings/            # 设置窗口
├── src-tauri/
│   ├── src/
│   │   ├── commands/        # 暴露给前端的 Tauri command（薄层，不写业务逻辑）
│   │   ├── db/              # SQLite 连接、迁移、仓储
│   │   ├── ai/              # LLM 客户端、工具契约、变更预览
│   │   ├── scheduler/       # 到点提醒的扫描与触发
│   │   └── window/          # 透明窗口、点击穿透、托盘
│   └── assets/pets/         # 内置像素形象（规格见 PET-ASSETS.md）
└── .claude/                 # Agent 配置（rules / settings）
```

**`commands/` 是薄层**：只做参数校验和调用，业务逻辑放在 `db/`、`ai/`、`scheduler/` 里。否则 command 会迅速膨胀成一个什么都干的文件，且无法单独测试。

## 数据流

```
用户说话/打字
   → 前端采集，交给 Rust command
   → ai/ 组装请求，带上当前待办上下文，调用用户配置的模型
   → 模型返回工具调用（增/删/改/查）
   → ai/ 把它渲染成人话变更预览，回传前端
   → 用户确认
   → db/ 落库
   → 前端刷新清单，宠物做一个反馈动作
```

关键点：**模型的输出不会直接落库**，中间必须经过用户确认。理由见 `AI-PIPELINE.md`。

提醒是另一条独立的流：`scheduler/` 定时扫描到期任务 → 检查免打扰状态 → 通知前端播放冒泡动画 + 发系统通知。

---

## 密钥存储

API Key 存入 Windows 凭据管理器（mac 上用 Keychain），**不写入配置文件、不写入数据库、不落明文**。配置文件里只存 `base_url` 和 `model` 这类非敏感项。
