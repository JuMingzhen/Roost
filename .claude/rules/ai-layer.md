# AI 层规则

适用于 `src-tauri/src/ai/`。完整契约见 `docs/AI-PIPELINE.md`——**改这里之前先读它。**

## 契约同步

工具的名称、参数、语义有任何改动，**必须在同一个 commit 里同步更新 `docs/AI-PIPELINE.md`**。文档和实现分叉之后，下一个 session 会照着错的文档改，代价比现在多花两分钟大得多。

## 写操作必须经过预览确认

模型返回的任何写操作（`create_task` / `update_task` / `set_progress` / `delete_task`）**一律不直接落库**。必须先渲染成人话变更预览、由用户确认。

不要为了"省一步"加任何绕过路径。BYOK 下我们无法保证用户配置的模型质量，模型误删用户攒了两周的计划是不可挽回的失败，而多一次点击成本极低。

即使将来放宽，也只放宽到「纯新增可配置免确认」。**删除和批量修改永远需要确认。**

## Prompt

- system prompt 单独成文件，不散落在代码里。
- **prompt 改动必须附带回归用例**，覆盖：新增带时间、新增不带时间、修改时间、改进度、删除、一句话含多个操作、模糊表述（应当追问而不是瞎猜）。
- 没有回归用例的 prompt 改动等于盲改——同一句话在改动后可能变成完全不同的操作，而这直接作用在用户的真实计划上。

## 时间

- 当前本地时间和时区注入 system prompt，让模型返回带时区的 ISO 8601 绝对时间。**不要让模型返回「明天」这类相对词再由代码解析**——那等于把歧义留到最后一步。
- 「今天」的边界用用户设定的一天起点，**只能有一处实现**，与今日视图共用同一个函数。

## 上下文注入

带上当前时间和活跃待办列表（**必须含 id**，否则模型无法引用已有待办）。

待办列表**要限量**——不能把全部历史塞进去，那会随使用时长线性推高每次调用的成本，而这笔钱是用户在付（BYOK）。

## 协议

只实现 OpenAI 兼容的 `chat/completions`（`docs/DECISIONS.md` D6）。要加其他协议的 adapter，先提案。

## 失败处理

`docs/AI-PIPELINE.md` 有一张完整的失败对照表。核心原则：**任何 AI 相关的失败都不能影响本地待办的正常使用**——没有 key、断网、模型挂掉，Roost 都还是一个完整可用的本地待办工具。
