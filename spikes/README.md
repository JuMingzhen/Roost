# M0 技术验证

本目录验证首选方案：**C# / .NET Framework 4.8 + Windows Forms + Win32 互操作**。三项验证均由脚本生成 JSON，并用退出码给出通过或不通过。

## 运行环境

- Windows 10/11；系统需带 .NET Framework 4.8/4.8.1。
- 不要求安装 .NET SDK。`build.ps1` 使用系统自带的 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`。
- 点击穿透会在临时测试窗口内注入鼠标点击；像素测试会短暂显示无边框测试窗口；CPU 测试会显示一个 96×96 动画块。

## 命令

```powershell
# 单项
.\spikes\run-click-through.ps1
.\spikes\run-pixel-clarity.ps1
.\spikes\run-cpu.ps1                 # 600 秒可见 + 30 秒隐藏

# 全部；约 11 分钟
.\spikes\run-all.ps1

# 仅检查脚本能否运行；CPU 时长不满足正式验收，因此整体会返回失败
.\spikes\run-all.ps1 -Quick
```

输出写入 `spikes/out/`（Git 忽略）。本次基线证据保存在 `spikes/evidence/2026-09-20/`。

## 判定口径

### 点击穿透

- 下层计数窗口和透明置顶窗口属于两个不同进程。
- 透明窗口只给精灵矩形设置 Win32 窗口区域（`SetWindowRgn`）。
- 每个显示器、100% 和 150% 场景各注入 12 次空白点击、2 次精灵点击。
- 空白点击必须全部被下层窗口收到，精灵点击必须全部被置顶窗口收到。
- JSON 的 `functionalPass` 表示落点功能是否通过；`hardwareCoverage.complete` 表示本机是否真的同时提供所需缩放组合。不存在的缩放只做 `simulated-geometry`，不能冒充真实显示器验收。

### 像素清晰

- 使用 16×16、含透明背景的测试精灵，按 2× / 3× / 4× 三档整数倍率渲染。
- 分别以 100% / 125% / 150% 布局尺寸创建窗口，并以 HWND 的完整物理分辨率截图。
- 自动扫描精灵矩形：每个像素只能属于原图不透明色或背景色；出现任何中间色即失败。
- `simulated-layout` 只证明布局与渲染算法，不替代对应缩放显示器上的真实截图。

### 待机 CPU

- 8 FPS（125 ms 一帧）连续播放 600 秒，每秒采样 Working Set。
- CPU 使用 `Process.TotalProcessorTime / 墙钟时间 / 逻辑处理器数` 计算，与任务管理器的整机百分比口径一致。
- 随后隐藏窗口 30 秒并停止计时器；隐藏期帧数增量必须为 0。
- 正式通过条件：可见期平均 CPU ≤ 0.5%、峰值 Working Set ≤ 100 MB、隐藏期动画完全暂停、可见采样时长 ≥ 600 秒。

## 已知限制

本次机器实际只暴露一台 200% 缩放显示器。脚本已覆盖当前显示器，并模拟 100% / 125% / 150% 的布局数学，但 PRD 指定缩放比例的真实硬件验收仍需在对应显示器设置下重跑。改变 Windows 显示缩放属于系统设置，本次没有自动修改；用户已决定把实机复测延期到 M1 完成后。多显示器不再是 PRD 要求。
